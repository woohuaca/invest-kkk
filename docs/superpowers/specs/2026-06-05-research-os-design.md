# Research OS 设计规格

## 结论

`research-os` 是一个服务二级市场股票投资决策的长期研究操作系统。它不以资料收集为终点，而以提高买入、卖出、观望、仓位和跟踪决策质量为目标。

第一版采用“决策中心 + 能源行业样板”的设计：顶层信息流围绕投资决策组织，第一批行业研究用能源行业跑通结构。

## 设计目标

### 核心用途

`research-os` 的首要用途是支持长期基本面为主、兼容中期周期变量的股票投资决策。

它需要回答五类问题：

1. 这家公司是否值得长期拥有？
2. 当前行业和周期位置是否支持买入？
3. 估值是否提供足够安全边际？
4. 应该买入、卖出、观望，还是调整仓位？
5. 哪些事实会证明原判断错误？

### 非目标

第一版不追求覆盖所有行业、所有资产类别或自动化交易。

第一版也不把研究系统做成泛知识库。所有文件都必须能说明自己如何进入投资判断，或者如何改善未来投资判断。

## 信息流

核心信息流如下：

```text
投资信念 -> 分析框架 -> 行业研究 -> 公司评分 -> 投资决策 -> 持续观察 -> 修正假设
```

每一层的职责不同：

1. `beliefs/` 定义长期不轻易改变的投资信念。
2. `frameworks/` 把信念转化为可复用分析方法。
3. `industries/` 沉淀行业层面的结构性判断。
4. `observations/` 记录事实，不急着下结论。
5. `insights/` 把事实提炼成可验证判断。
6. `decisions/` 形成投资动作和复盘条件。
7. `agents/` 定义 AI 或研究助手执行任务时应遵守的工作方式。

## 目录职责

### `beliefs/`

`beliefs/` 存放长期投资原则。这里的内容应该少而稳定，用来约束后续判断。

初始文件：

- `investment-principles.md`：定义什么样的公司值得长期拥有，以及什么样的收益不值得追。
- `control-rights-theory.md`：分析谁掌握产业链控制权、议价权和利润分配权。
- `bottleneck-theory.md`：分析行业瓶颈在哪里，以及瓶颈如何转化为超额收益。

### `frameworks/`

`frameworks/` 存放可复用分析框架。它们不是结论，而是做判断的方法。

初始文件：

- `industry-analysis.md`：通用行业分析框架。
- `energy-framework.md`：能源行业专用分析框架。
- `company-score-model.md`：公司投资评分模型，服务买入、卖出、观望和仓位判断。

### `industries/`

`industries/` 存放行业研究资产。第一版只创建能源行业样板。

`industries/energy/` 初始文件：

- `value-chain.md`：能源价值链、利润池、瓶颈和周期风险。
- `players.md`：主要玩家类型、代表公司和竞争逻辑。
- `indicators.md`：需要长期跟踪的价格、供需、库存、资本开支、政策和财务指标。
- `hypotheses.md`：当前对能源行业最重要的可证伪假设。

### `observations/`

`observations/` 记录原始事实，例如财报、新闻、政策、价格变化、行业数据、调研纪要。

这里的内容应尽量区分事实和解释。事实可以进入多个不同判断，不能因为当下投资倾向而被提前筛选。

### `insights/`

`insights/` 存放从观察中提炼出的判断。

一个 insight 必须说明：

- 它来自哪些事实。
- 它改变了哪个行业、公司或周期判断。
- 它的置信度是多少。
- 它如何被反证。

### `decisions/`

`decisions/` 是系统的中心。所有研究最终都应服务这里。

一个投资决策至少包含：

- 标的。
- 动作：买入、卖出、观望、加仓、减仓。
- 仓位建议或仓位区间。
- 核心投资结论。
- 支撑依据。
- 估值和安全边际。
- 主要风险。
- 反证条件。
- 跟踪指标。
- 复盘日期或复盘触发条件。

### `agents/`

`agents/` 存放给 AI 或研究助手使用的任务说明。

第一版可以先保留为空目录，后续再补充行业研究、公司初筛、财报分析、决策复盘等 agent 指令。

## Markdown 模板原则

所有 Markdown 文件默认使用结论先行结构：

```md
# 文件标题

## 结论

一句话说明当前判断。

## 为什么重要

说明它如何影响投资决策。

## 判断框架

列出核心变量和判断标准。

## 当前判断

写清楚强判断、弱判断和未知项。

## 反证条件

说明哪些事实出现后，当前判断需要修改。

## 下一步观察

列出需要跟踪的数据、事件或问题。
```

不同目录可以调整侧重点：

- `beliefs/` 重原则和边界。
- `frameworks/` 重变量、权重和使用方法。
- `industries/` 重结构、周期和关键指标。
- `observations/` 重事实、来源和日期。
- `insights/` 重判断、置信度和反证条件。
- `decisions/` 重投资动作、仓位、估值、风险和复盘。

## 第一版范围

第一版创建用户给出的目录结构和 Markdown 文件，并为每个文件写入中文模板。

第一版不填充具体公司研究内容，不给出真实投资建议，也不引入复杂工具链。

第一版完成后，应能支持以下工作方式：

1. 从能源行业事实进入 `observations/`。
2. 从事实提炼判断进入 `insights/`。
3. 用 `frameworks/company-score-model.md` 对公司形成评分。
4. 在 `decisions/` 中形成投资动作和跟踪计划。
5. 复盘时回到 `beliefs/`、`frameworks/` 和 `hypotheses.md` 修正假设。

## 成功标准

第一版成功的标准不是文件数量，而是结构是否能降低投资判断成本。

具体标准：

1. 每个目录职责清楚，不互相替代。
2. 每个 Markdown 文件都有明确的投资决策用途。
3. 能源行业样板能承载行业、公司、指标和假设。
4. 决策记录能清楚表达动作、依据、风险和反证条件。
5. 后续扩展到其他行业时，不需要推翻顶层结构。

## 风险与约束

### 风险

1. 系统可能变成资料堆积，而不是决策系统。
2. 框架可能过度抽象，脱离具体投资问题。
3. 能源行业样板可能过度影响通用结构。
4. 决策记录如果不写反证条件，容易强化确认偏误。

### 约束

1. 所有内容默认使用中文。
2. Markdown 是源事实和源判断。
3. 文件结构保持简洁，不提前引入数据库、自动化脚本或复杂索引。
4. 第一版优先保证逻辑清楚，而不是覆盖全面。

## 实施边界

下一步实施只包括：

1. 创建 `research-os/` 目录。
2. 创建用户指定的子目录和 Markdown 文件。
3. 为每个 Markdown 文件写入与其职责匹配的中文模板。
4. 保持目录命名和文件命名与用户给出的结构一致。

下一步实施不包括：

1. 重命名文件。
2. 创建用户未要求的大量额外目录。
3. 填写具体公司投资结论。
4. 把系统扩展到能源以外行业。
